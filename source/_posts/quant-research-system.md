**量研观策是一套基于 Python、PostgreSQL、FastAPI 和 Vue 的个人量化研究系统。** 它把行情处理、因子计算、规则选股、机器学习和结果展示串成一条可复查的研究链路。

项目地址：[stock.cbsbm.cn](https://stock.cbsbm.cn/)

| 模块 | 已实现的核心能力 |
|---|---|
| 数据与因子 | 行情与财务整理、日频特征存储、数据质量检查 |
| 规则策略 | 低波动趋势回踩、突破准备度、突破形态观察、底部反转 |
| 因子研究 | 状态内分组、Rank IC、分期比较、区块 bootstrap |
| 机器学习 | XGBoost 回归、时间隔离滚动验证、绝对/相对收益目标对照 |
| Web 工作台 | 市场观察、个股分析、条件筛选、候选与模型记录、学习中心 |
| 部署 | 静态快照、只读查询、独立发布产物、Windows 到笔记本的数据同步 |

**当前定位：研究与工程实践，尚未证明稳定可交易的盈利优势，未接入实盘下单。**

## 1. 系统架构：计算、查询与展示分离

![系统架构图：Windows完成数据处理和研究，EdgeOne提供静态展示，笔记本承接股票中心查询](/img/posts/quant-system/architecture.png)

图 1：Windows 负责数据与计算，EdgeOne 提供静态页面和快照，笔记本只承接股票中心的动态查询。

| 层次 | 技术 | 职责 |
|---|---|---|
| 存储 | PostgreSQL、SQLAlchemy | 行情、因子、候选、缓存及查询快照 |
| 计算 | Python、Pandas、NumPy | 数据清洗、滚动特征、候选与统计分析 |
| 学习 | XGBoost | 从日频因子学习非线性收益排序关系 |
| 服务 | FastAPI、Nginx | 参数校验、只读查询、超时与并发限制 |
| 前端 | Vue、Element Plus、ECharts | 研究工作台、条件筛选、图表与文章 |
| 发布 | EdgeOne、JSON 快照、Cloudflare Tunnel | 静态内容分发与受控动态访问 |

设计上有两条数据路径：

- **静态路径**：后台生成市场、候选和模型快照，前端直接读取。公网静态内容缺失时报错，不转而请求笔记本。
- **动态路径**：Windows 导出股票中心数据，经校验后导入笔记本独立展示 schema；个股与筛选请求通过 Tunnel、Nginx 和 FastAPI 查询。

数据库不直接暴露公网。网页也不触发全市场计算、模型训练或研究回测。

## 2. 功能分层：因子、策略与信号各司其职

![功能框图：数据层提供统一因子，规则策略与机器学习分别消费数据，研究评估和网页负责验证与展示](/img/posts/quant-system/modules.png)

图 2：规则选股与机器学习是不同研究路径，不能把人工评分直接当作模型学习到的结论。

核心数据组织以“股票代码 × 交易日”为粒度：

- `daily_kline`：行情；区分复权分析价格与原始交易价格。
- `factor_daily`：可复用日频原子特征，不存策略状态和最终分数。
- `strategy_candidate`：按策略、版本、日期保存候选及评分分解。
- `screener_snapshot`：服务查询的行情、财务与股本汇总。

这种划分让同一份因子可以供不同策略和模型使用。修改候选规则时，不需要另建一套行情与因子链路；研究结果也能追溯到当时的版本和输入。

## 3. 四套规则策略：从形态描述到可计算条件

四套策略都先检查证券范围、关键字段和成交条件，再应用资格门槛与排序。**候选表示规则匹配，评分表示规则内的相对评价，不是上涨概率。**

| 策略 | 核心思想 | 主要观察量 |
|---|---|---|
| 低波动趋势回踩 V1 | 在市场条件允许时，观察上升趋势中的低波动回踩与恢复 | 指数趋势、市场宽度、ATR占比、距MA20距离、流动性 |
| 突破前准备度 V2 | 综合位置、趋势、波动收缩与相对强度，寻找临近前高的蓄势或触发形态 | 距60日高点、量比、市场/行业强度分位、MACD |
| 突破形态观察 V3.1 | 分开评价“临近突破前的安静状态”和“温和突破触发”，排除明显过热 | 距前20日高点、波动比、换手、量比、近期涨幅、价格冲击 |
| 底部反转 V1 | 观察较大回落后的缩量平台，以及量能、趋势和动量恢复 | 距长期高点、平台振幅、量能收缩/恢复、距平台位置 |

### V3.1：资格门槛与排序偏好分开

V3.1 不采用“涨得越多分越高”的思路，而是分三步处理：

1. **位置资格**：先判断是否处于规定的高位区域、是否接近此前高点。
2. **状态识别**：区分准备观察池与触发观察池。
3. **状态内评分**：准备阶段重视波动、换手与量能的安静程度；触发阶段增加当日涨幅、量能、收盘位置和突破距离评价，并剔除明显过热事件。

评分由准备质量、近期延伸程度和触发质量等分量组成。候选保存总分、分项、状态和入选依据，方便解释“为什么选中”。两个状态池的分数不能直接跨池比较。

V3.1 的触发态将波动分量权重由20调整为25、价格冲击由10调整为5，准备态不变。这是明确的研究版本，**尚未证明调权带来收益改善；旧 V3 研究结果不能直接作为 V3.1 的验收结果。**

## 4. 因子研究：先验证，再决定是否组合

因子层覆盖趋势、动量、量能、换手、波动和价格位置等特征。例如：

```text
波动比 = 20日收益波动率 / 60日收益波动率
量比   = 5日平均成交量 / 20日平均成交量
ATR占比 = ATR14 / 收盘价
```

比值低、高是否更有利，由研究回答，不在特征定义中预设。缺失、除零和无效输入需要单独处理。

![研究流程图：预登记问题和协议，经时点审计、因子或模型对照、执行审查后决定继续或停止](/img/posts/quant-system/research-flow.png)

图 3：研究可以在数据或执行条件不足时停止，不要求每个课题都输出一条收益曲线。

### 单因子如何检验

在相同日期、相同观察状态内，按因子值分组，比较未来收益，避免把不同市场日期直接混在一起：

- **Rank IC**：因子排名与未来收益排名的相关性。
- **Q5−Q1**：高因子组与低因子组的收益差，检查两端是否有区分度。
- **分期比较**：按年份、半年和状态检查方向是否延续。
- **日期区块 bootstrap**：按日期块重采样，评估重叠持有期下的不确定性。
- **覆盖与成本审查**：同时报告缺失标签、极端贡献和固定成本敏感性。

V3 系统研究固定比较七项特征、准备/触发两类状态，以及5/10/20日标签。主要结果是：准备态没有发现稳定的十日两端差异；触发态有局部排序线索，但新增因子与模型扩展没有形成跨期稳定增量。

这些结果来自已用于探索的历史，不能当成独立留出确认。因此，项目没有把历史分组收益差直接换算成生产评分权重。

## 5. 机器学习：让模型学习收益，而非复述人工分数

离线特征学习入口使用 `factor_daily` 的44项数值原子特征，输入不包含人工策略分数或未来标签，也不先按旧策略候选筛选训练样本。

模型采用 XGBoost 回归树，学习非线性关系和特征交互。首版固定树深3、150轮、学习率0.05，不在测试期搜索参数。

### 标签与时间隔离

默认标签是 T+1 开盘至 T+10 收盘的前复权收益：

```text
y_abs(i,t) = Close_qfq(i,t+10) / Open_qfq(i,t+1) - 1

y_rel(i,t) = y_abs(i,t) - 同一信号日训练样本的未来收益均值
```

第二个目标用于研究相对表现：减少市场同涨同跌对学习目标的影响。**同日未来均值只用于构造监督标签，不进入预测输入。**

验证采用按日期扩展训练、滚动测试：至少252个成熟训练日期，每63个日期滚动一次。训练标签必须在测试边界之前结束；所有股票按同一日期边界切分，不能随机打散股票行。

测试时先预测、排序、选 Top20，再检查未来标签。选中股票有未知标签时，不用后来有完整数据的低排名股票替补。输出预测、折边界、覆盖率、同日基线、置换重要性和输入哈希。

### 一次只改训练目标的对照

2026年10月18日归档的 V1/V2 实验，固定输入、44项特征、11折边界与模型参数，只改变绝对/相对收益目标：

| 指标 | 归档结果 | 解释 |
|---|---|---|
| 全期平均 Rank IC | V1 0.0391 → V2 0.0947 | 按各日成对有效标签计算的排序指标 |
| 403个共同严格完整日期 | V2−V1 十日均值增量 +0.914个百分点 | 95%探索区间为 [+0.283, +1.538] |
| 364个共同执行代理完整日期 | V2−V1 十日均值增量 +0.645个百分点 | 95%探索区间为 [+0.033, +1.246] |

相对目标提供了值得继续研究的增量，但模型仍存在标签与执行未知。**这些数值是持有期统计，不是年化收益或真实账户净值；执行代理也不等于真实成交。**

这里的 V1/V2 是离线回归研究版本，与突破策略 V2、V3.1，以及网页中的旧分类评分记录分别管理。

## 6. 数据质量与工程实现

| 问题 | 实现方式 |
|---|---|
| 不同价格口径混用 | 连续收益/技术研究使用一致复权口径；市值使用原始价格与股数，不拿前复权价估算 |
| 错误数据污染截面排名 | 先隔离重复、无效OHLC、缺量额和越界因子，再计算上下文与评分 |
| 网页反复触发重计算 | 后台任务计算，查询侧读取缓存、快照和有限范围数据 |
| 数据同步后口径不一致 | 导出一致性快照，校验字段、行数、日期和SHA256；笔记本展示表事务替换，失败回滚 |
| HTTP 200却返回HTML | 校验 Content-Type、JSON结构与必需字段，不只判断状态码 |
| 失败被显示成零结果 | 分开处理请求失败、数据过期、归档与有效空结果；候选是否已生成仍需独立状态证据 |
| 研究难以复现 | 保存协议、配置、版本、输入指纹与逐期输出；保留旧结果，不静默覆盖 |
| 发布混入源码或凭据 | 独立发布仓库、文件白名单与敏感内容检查，仅上传允许的构建产物 |

目前最关键的缺口仍是账户与执行：历史证券身份、权威限价、公司行动和退出路径尚未全部验收。事件研究没有处理完整现金与持仓约束，不能据此给出可信的账户年化、最大回撤或夏普。

项目下一阶段优先核验已有研究的执行疑点、补齐账户记账和固定版本的新增期观察，不继续无边界扩充指标与模型。
