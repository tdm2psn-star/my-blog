## 1. 文章发布流程与技术细节

在 Hexo 体系中，文章遵循“源码编写 -> 静态编译 -> 全局发布”的生命周期。

### 1.1 核心命令
```bash
# 创建新文章（默认类型为 post）
hexo new post "文章标题"

```

执行后，系统会在 `source/_posts/` 目录下同步生成 `文章标题.md` 及对应的资源文件夹（需开启配置）。

### 1.2 前置参数 (Front-matter)

Markdown 顶部的 YAML 配置区域用于定义页面属性：

* **title**: 页面标题。
* **date**: 写作时间，决定时间轴排序。
* **cover**: 封面图 URL，建议尺寸 1920x1080 以适配安知鱼主题。

## 2. 图片管理方案：本地资源文件夹

对于追求数据资产完整性与离线备份的开发者，推荐使用 Hexo 的**资源文件夹模式**，配合 Typora 可实现极佳的写作体验。

### 2.1 开启模式

在项目根目录 `_config.yml` 中修改：

```yaml
post_asset_folder: true

```

**逻辑说明**：开启后，每次 `hexo new` 都会生成一个与 `.md` 同名的文件夹，专门存放该文章的图片资产。

### 2.2 配置 Typora 实现“粘贴即上传”

通过 Typora 的自动化功能，可以省去手动移动图片和修改路径的繁琐步骤：

1. **偏好设置**：打开 **图像** 选项卡。
2. **插入图片时**：选择 `复制到当前资源文件夹`。
3. **路径约束**：勾选 `优先使用相对路径`。

### 2.3 最佳实践工作流

1. **初始化**：终端输入 `hexo new post "Project-Showcase"`。
2. **编辑**：使用 Typora 打开 `source/_posts/Project-Showcase.md`。
3. **插图**：直接将截图拖入编辑窗口或 `Ctrl+V` 粘贴。
* **底层行为**：Typora 会自动将图片存入 `source/_posts/Project-Showcase/` 目录。
* **渲染路径**：Markdown 源码会自动转换为 `![描述](Project-Showcase/image.png)`，完美匹配 Hexo 的路径解析规则。

## 3. 进阶方案：外部图床 (远程托管)

若需减轻服务器带宽压力或提高全球访问速度，可选择图床方案。

* **工具**：**PicGo** (开源图床管理工具)。
* **托管**：推荐使用 GitHub 仓库或阿里云 OSS。
* **逻辑**：截图后通过 PicGo 上传至云端，直接在 Markdown 中引用远程 URL。这种方案更利于多端同步，但依赖图床服务的稳定性。

## 4. Markdown 行文规范

作为技术文章，建议遵循以下排版规则：

### 4.1 层级逻辑

* 使用 `##` 标注章节，`###` 标注小节。严禁跨级使用标题（如 `##` 后接 `####`），这会破坏 SEO 和侧边栏索引。

### 4.2 代码规范

必须注明代码块语言，以便安知鱼主题进行语法高亮：
```java
// Android 示例代码
Log.d("TAG", "Hello Hexo");
```

## 5. 自动化发布

创建 `deploy.sh` 脚本收敛常用操作，提高发布效率：

```bash
#!/bin/bash
# 清理缓存、生成静态文件并推送远程
hexo clean && hexo g && hexo d
echo "Deployment Complete."

```
